# Visible ESP / 可见视觉辅助

基于 `dev-0.16.1.35392`，针对 EFT 0.16.1.35392 / SPT 3.11.x。
人物和物品使用独立的屏幕空间描边与半透明填色，保留模型原材质。新渲染不依赖旧的 `outline`，该资源仍供手雷功能使用。

## 人物描边与填色

在「玩家 ESP」中开启显示描边，并保持「描边与填色」总开关开启。

| 设置 | 行为 |
| --- | --- |
| 显示描边（ShowCharms） | 人物描边和填色开关，与二维 ESP 分开。 |
| X射线视野（XRayVision） | 新配置默认关闭，墙体遮挡的人物部分不显示；开启后使用遮挡填色。已有配置保留原值。 |
| 阵营颜色 – 颜色（Color） | 可见部分内部填色。 |
| 阵营颜色 – 边框颜色（BorderColor） | 外边线颜色。 |
| 遮挡剪影颜色（OccludedColor） | X-Ray 开启时的内部填色。 |
| 遮挡不透明度（OccludedOpacity） | 0–1，默认 0.55。 |
| 人物填色不透明度（BodyTint） | 0–1，默认 0.3；0 只显示边线，1 完全覆盖底色。与颜色自身的 alpha 相乘。 |
| 描边粗细倍率（OutlineScale） | 默认 1 对应 2 个渲染像素，实际宽度限制为 1–5 像素，不随距离膨胀。 |
| 最大距离（MaximumDistance） | 同时限制人物二维 ESP 和人物描边，0 表示不限制。 |

颜色及透明度即时更新。所有材质子网格均参与描边；身体和装备合为人物轮廓，不在每块衣服之间重复描边。人物皮肤缓存每 2 秒刷新以跟进装备变化。普通视角与开镜分别筛选和绘制，背包预览相机不参与。

人物描边、方框、骨骼和信息均使用各阵营的独立颜色，已移除“统一 ESP 配色”。新配置的边线与阵营填色一致：BEAR 蓝色、USEC 绿色、Scav 黄色、Boss 红色、邪教徒紫色、Raider 橙色、Rogue 灰色。已有自定义阵营颜色继续保留，可分别修改填色、边框和信息颜色。

「玩家 ESP → 显示队友」默认关闭，同时控制队友的描边、填色、二维 ESP 和雷达/地图标记。开启后使用独立的「队友颜色」，默认青色，也可分别调整边框、填色、遮挡和信息颜色；队友不受“可射击变色”覆盖。组队判断使用有效且相同的 GroupId，以及 AI 跟随队长的关系，支持 FriendlyPMC / FriendlyFireTeam 随从；同阵营本身不代表队友。雷达/地图仍遵循各自的类别与距离开关。

渲染在 `BeforeForwardAlpha` 执行，赶在 EFT 的 SSAA/DLSS 和后处理采集画面之前，避免高亮画到已经不再用于输出的缓冲区。可见/遮挡部分直接使用相机原有深度附件，Shader 不写入、不清除场景深度，也不依赖 `_CameraDepthTexture` 或物理射线。这样镂空网孔按真实几何深度显示，之后绘制的透明玻璃仍能正常叠加；开启 X-Ray 才显示实体墙后的人物。特殊材质若自身写入整片深度，仍按该材质的实际行为遮挡。

## 物品、容器、门与性能设置

「描边与填色」页提供散落物品、可搜索容器的独立开关和颜色，任务物品单独配色。包含丢在地上的物品，不显示容器内部没有世界模型的物品；不改变物品追踪列表或二维标签设置。

门也在这一页：默认开启、金黄色、距离 10 米、填色不透明度 0（只描边）；门的开关、颜色、距离和填色可独立调整。门扇开合时轮廓跟随模型，不改变锁定或交互状态。只处理有 `Door` 组件的门，不把静态装饰墙面当作门。

容器的交互组件可能位于盖子或单独的碰撞节点。模型收集会包含交互节点、游戏明确关联的容器对象和合适的直接父节点，从而覆盖旁边的箱体/旅行包/医疗包模型。父级补全限制扫描节点数及尺寸，遇到其他交互对象的共享父节点就停止；阴影代理模型不参加描边。门优先只收集移动门扇，避免把墙面、门框等固定父级几何一起描亮。

| 设置 | 默认及含义 |
| --- | --- |
| 物品描边距离 | 10 米，范围 1–100 米。 |
| 物品填色不透明度 | 0.12，设为 0 可只看边线。 |
| 物品、容器与门边线宽度 | 2 像素，可调 1–5。 |
| 屏幕中心半径 | 0 = 全视野；可改为 300–500 像素减少选中目标。包围盒碰到该区域就算选中，避免只检测中心点漏掉画面边缘目标。 |
| 物品、容器与门描边总上限 | 共用 64 个，优先附近且通过视野筛选的对象。 |

物品、容器和门只显示可见部分。附近候选列表每 0.5 秒刷新，场景门和容器每 10 秒扫描一次；另外从世界已登记的战利品列表补收动态容器，不仅依赖地图预先登记的容器。附近模型引用每 2 秒刷新，跟进延迟加载和层级变化；已缓存模型的位置及旋转随每帧绘制更新。拾取、生成后的候选列表最多有相应刷新延迟。主相机和瞄准镜各自进行包围盒、距离与屏幕范围筛选。人物和场景对象共用每相机一组临时纹理，空场景不申请纹理；像素扩展只覆盖目标所在的屏幕区域。不逐帧创建材质、不烘焙蒙皮网格，也不改写原模型材质或强行开启被游戏关闭的渲染器。

由于尊重游戏的渲染器启用状态，X-Ray 无法保证显示已被游戏彻底停用或卸载的模型。DLSS/FSR、夜视、热成像和具体瞄具效果仍需游戏中实测；宽度以实际渲染分辨率为准。

## 构建与安装

C# 使用 Visual Studio MSBuild 和 .NET Framework 4.7.1 目标包；Shader 使用 Unity **2022.3.43f1**。项目中含已构建资源，修改 Shader 后必须重新构建：

```powershell
.\Build-Shaders.ps1 -Test
.\Build-Local.ps1 -GamePath E:\EFT\SPT_3114 -Language zh-cn -Test
# 或一次执行（同时构建 Shader 并做渲染检查）
.\Build-Local.ps1 -GamePath E:\EFT\SPT_3114 -Language zh-cn -BuildShaders -Test
```

构建检查 Shader 源码和资源包哈希，阻止旧资源混入新包。Unity 图形检查使用实际打包的 Shader，在前向与延迟渲染路径检查透明度、遮挡、X-Ray、多层叠加、蒙皮网格、无 ShadowCaster 的镂空铁丝网、透明玻璃和资源清理。另有先采集再输出的后处理回归测试，以及缩小/带偏移视口的对齐检查；输出在 `artifacts/shaders`。这些是独立测试场景，不代表真实 DLSS 算法或游戏实测。

模型层级检查覆盖盖子与箱体分离、包体与交互碰撞节点分离、显式模型引用去重、拒绝共享/过大的场景父级、排除阴影代理、门扇开合和延迟加载部件。实机仍需检查各地图的特殊容器；`trainer-highlights.log` 的 `Models` 行记录附近对象的类型、节点名、父节点及收集到的模型/子网格数量，便于定位具体遗漏。

`Build-Local.ps1 -Test` 还运行配置与队友回归检查：从缺失目录首次保存、向新对象加载嵌套 RGBA/开关/快捷键、手动还原、备份替换、文件锁定时保护原文件、损坏属性隔离，以及普通队友/自己的 AI/敌方随从/解散随从的区分。测试调用实际配置与队友判断代码，游戏对象使用最小替身；独立 Windows 测试程序使用 MSBuild 自带的同程序集版本签名 JSON 库，游戏 DLL 仍引用游戏自带的库。

中文包位于 `artifacts/visible-esp-zh-cn`，英文版本用 `-Language en`。包内包含 DLL、`trainer-highlights`、资源校验信息、安装脚本和说明，不包含游戏程序集。

退出游戏后运行：

```powershell
.\artifacts\visible-esp-zh-cn\Install-Local.ps1 -GamePath E:\EFT\SPT_3114
```

安装器将备份、替换并校验这两个文件；安装失败会恢复之前状态：

- `EscapeFromTarkov_Data/Managed/NLog.EFT.Trainer.dll`
- `EscapeFromTarkov_Data/trainer-highlights`

备份位于 `TrainerBackups/时间戳`，`installation.json` 记录目标和原文件是否存在。回退时退出游戏，将备份中的 DLL 和资源复制回对应位置；若之前没有新资源，可删除该单个资源文件。原 `outline`、BepInEx 加载插件、配置和存档保持原样。

启动后独立日志写入 `<游戏>/trainer-highlights.log`（经 MO2 启动时也可能位于其 overwrite 目录）。进入战局后应记录 `Shaders loaded; event=BeforeForwardAlpha`。每 5 秒记录一次目标收集状态和相机绘制统计，包括开关、相机、尺寸、视口、候选数量、选中数量和绘制次数；日志超过 1 MiB 后轮换。EFT 可能屏蔽普通 `Debug.Log`，因此排错以此文件为准。缺失资源、收集或渲染异常会记录明确错误。退出时先按 Unity 原生对象状态检查资源，避免对已经释放的 AssetBundle 再次 Unload。

## 设置

Insert 打开训练器，进入玩家 ESP 页。设置区域可以滚动。

| 设置 | 行为 |
| --- | --- |
| 仅显示可见部位（VisibleOnly） | 默认开。完全遮挡时隐藏普通 ESP；关节及骨段分别检测。关闭恢复穿墙 ESP。 |
| 现代 ESP 样式（ModernEsp） | 默认开：角框、淡色填充、左侧血条、上方武器、下方距离、简化骨架。关闭使用完整方框和传统骨架/信息布局。 |
| 显示骨骼（ShowSkeletons） | 新配置默认开；旧配置的开关值保留，必要时手动打开。 |
| 框内不透明度（BoxFillOpacity） | 默认 0.08，取值 0–1；0 关闭填充。只在显示方框且现代样式开启时生效。 |
| 显示队友（ShowTeammates） | 默认关，同时作用于描边、二维 ESP 和雷达/地图。 |
| 队友颜色（TeammateColors） | 独立设置队友填色、边线、遮挡剪影和信息颜色。 |
| 显示信息（ShowInfos） | 血条、武器、距离的总开关。三者另有独立开关。 |
| ESP 字号（EspTextSize） | 默认 14，可调 10–28。 |
| 显示关节点（ShowJoints） | 现代样式的实心圆点，默认开。 |

骨骼和方框线宽继续使用原有选项。确认效果后通过总览中的“保存”持久化。
总览显示保存/加载结果及实际配置路径（Windows 文档目录下的 `Escape from Tarkov/trainer.ini`）。首次保存自动创建目录；后续保存保留上一版 `trainer.ini.bak`，写入失败时不覆盖原文件。启动时自动加载，手动加载也会重置颜色选择器和输入框缓存。无效配置项会单独跳过并报告，不影响后续有效设置；旧版统一配色字段会被忽略。
XRayVision 仍仅控制人物上色，与 VisibleOnly 相互独立。

## 遮挡与性能边界

- 使用摄像机到关节的物理射线，忽略自身及目标身体，检查世界遮挡物。沿用原 Shootable 的碰撞层。
- 骨段需两端与中点均无遮挡；这是保守的采样近似，不是逐像素裁剪。狭窄露出的肢体可能不显示，细小遮挡也可能落在采样点之间。
- 只有主要关节点至少一个位于画面内且可见时才显示整人角框及信息。局部可见时，角框/填充仍是整个人的提示；不想要这个提示可关闭“显示方框”。
- 烟雾、灌木、玻璃及特殊材质没有专门处理，结果取决于游戏碰撞体。
- 仅在 GUI 重绘事件绘制，关节投影和可见性按当前帧共享，不跨帧保留可见结果。现代骨架没有手指细节。
- 线段按屏幕和镜内圆形边界裁剪；框填充、血条和文字在镜边放不下时保守隐藏。
- 所有功能的实际帧率影响需在相同地图、AI 数量及视角下比较。可先关闭骨骼，仅保留角框和信息，以降低射线及绘图开销。

## 游戏内验收

1. 完全被实墙挡住：普通 ESP 消失；露出头/手/腿时只提示采样可见部分。
2. 同一敌人快速进出掩体：没有跨帧缓存造成的额外拖尾。
3. VisibleOnly 开关：可见模式与穿墙模式可以来回切换。
4. 现代/传统样式切换；原有 Shootable 颜色仍可独立启用。
5. 瞄准镜、屏幕边缘、蹲姿、趴姿、近距离：没有镜边连线和巨大错误骨架。
6. 调整填充、颜色、字号、线宽，保存、重启后确认保留。
7. XRayVision 开关仍按原样控制上色。
8. 「显示队友」关闭时队友的描边/ESP/雷达均隐藏，敌人保留；开启后队友使用独立颜色。分别检查普通组队与友方 AI 随从。
9. 总览点“保存”后显示成功；改动设置再点“加载”能恢复，退出并重新启动也能恢复。确认阵营、队友颜色及门/容器开关一起保留。

ESP 自动测试验证裁剪几何及异常数据处理，描边另有 Unity 图形检查；二者均不能替代上述游戏内验收。
